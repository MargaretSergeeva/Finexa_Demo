Finexa · Data Pipeline Architecture

12-Week Hybrid Agentic System Pilot · Payments Domain · BigQuery as single source of truth · Appsmith as orchestrator & UI

Design principle: the model produces content; deterministic code performs consequential actions. Four sequential commands plus /ask-data in parallel, three human gates, and no AI component holding Jira credentials.

End-to-End Flow

1 · Ingest & De-identify
CRM notes
Support tickets
Interview transcripts
Other channels
Google Cloud DLP
Scrubs PII and sensitive financial data at ingestion. The AI service account holds no credential to raw source data, so PII is unreachable by design.
→ Writes to raw_feedback (linked to merchants)
↓
2 · /process-feedback Assist
Splits one transcript or ticket into distinct problems, each with summary, pain points, root cause and a provisional theme. Thin material halts and asks for clarification rather than guessing.
→ Writes to processed_insights (+ embedding for vector search, theme from feature_area_taxonomy)
↓
3 · /log-feedback Assist
Vector search finds similar confirmed issues; the command proposes whether this is the same issue as an existing opportunity or something new.
→ Writes to candidate_shortlist and logged_feedback_pending
↓
4 · Human Gate 1 — Confirm reading & grouping
PM verifies
A verification task with a checkable answer: attach to an existing opportunity, create a new one, or reject. The only gate designed to graduate to spot-checks once agreement rates are sustained.
→ gate_decisions (ai_proposed_value vs. pm_final_value) · creates/updates opportunities
↓
5 · Score Opportunity Deterministic + /prioritize-opportunities Augment
Priority score = weighted sum of five inputs, pulled from evidence already in the system: customer value (Enterprise vs. SMB), urgency (worst severity + recurrence), strategic alignment, operational risk, compliance sensitivity. Arithmetic, not a model call. Weights are versioned and tunable.
The command only explains the score in plain language; it never calculates it. Implementation complexity is excluded and set manually at Gate 3.
→ opportunities.priority_score, priority_explanation, priority_weights_version
↓
6 · Human Gate 2 — Worth drafting now? (permanent)
PM decides
A judgment task shaped by capacity and timing. No single correct answer, so this gate never graduates.
→ approved_for_drafting = true · logged in gate_decisions
↓
7 · /draft-user-story Assist
Converts the approved opportunity into problem statement, user story, acceptance criteria and evidence-linked rationale.
→ jira_tickets (draft)
↓
8 · Human Gate 3 — Draft & complexity (permanent)
PM / Engineering Lead confirm
Checks the draft against the original evidence, assigns implementation complexity, confirms for Jira.
↓
9 · Wrapper Code → Jira Deterministic
The only component holding Jira credentials posts selected drafts to Jira. No AI output can reach engineering unreviewed: a structural guarantee, not a policy.
Status sync → jira_status_log. New insights on a resolved opportunity → regression_flag + last_insight_at, surfacing post-release regressions.
In parallel · /ask-data Augment · read-only
Plain-language querying of stored insights at any time via an MCP-based analytical agent, alongside Appsmith dashboards. Three layers: Product, Process and AI Operations analytics (ai_run_metrics).
